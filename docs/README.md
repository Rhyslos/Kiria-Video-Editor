# docs

Plans, research notes, decisions and the user guide. Code comments explain *how*; these files explain *what* and *why*.

| File or folder | What it holds |
|---|---|
| [project-plan.md](project-plan.md) | What the app is: principles, working rules, pages, effects, architecture |
| [build-plan.md](build-plan.md) | How and in what order to build it: phases, step checklists, gates |
| [research/](research/) | One note per big system, written before building it |
| [decisions/](decisions/) | Short records of decisions that changed the plan |
| [user-guide/](user-guide/) | The user guide people read: one HTML page with screenshots, shipped with every installer and opened from Settings › Help and F1 |

Keep both plans current: tick steps in `build-plan.md` in the same commit as the work, and update `project-plan.md` before changing anything that was agreed there.
