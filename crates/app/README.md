# app

The editor window and its five pages. Binary name: `editor`.

## Status

Phase 0.6 done: the window, the shared top bar, five empty pages that switch instantly, shortcuts, Settings, search for commands, inline errors and Diagnostics. Autosave runs on a worker. The pages fill up from Phase 4.

Phase 4A so far: importing media (Ctrl+I, the Import button, or dropping files on the window), the viewer with its transport, the timeline (click a clip to select it, drag to move it, drag its edge to trim; V, B, R, T, Y and U pick the Select, Blade, Ripple, Roll, Slip and Slide tools; N snapping; audio tracks show waveforms and have mute, solo and volume; Delete, Backspace and S act on the selection; drag the red needle; Ctrl+wheel zooms at the pointer, = and - zoom in and out, \\ shows it all, Shift+wheel pans, the middle button drags the view), playback with sound (Space plays; pausing goes back to where playback started, Stop stays), a scrub bar and preview quality (Left/Right step a frame, Home/End jump), and Timeline settings (Automatic until the first video is imported, a template, or the same as one of the project's videos). Every track's height can be changed (drag the edge of its name, double-click for the usual height, Alt+wheel or Alt with = and - for every track of an area; Alt+\\ puts them back); heights and the divider between video and audio are kept per project. The handle between the viewer and the timeline shares the height between them (drag it; double-click for the usual split), and is remembered. Templates (Ctrl+T, or the Templates… button) keep an intro or outro to drop into any project. Also: Ctrl+/ for the keyboard shortcuts page (every shortcut can be changed there; changes are kept in settings and used by the launcher too; "Cheat sheet…" saves a page to print), F for a full-screen viewer (Escape returns), the region and timeline labels (Shift-drag in the ruler, L loops, right-click menu), the project picture for the launcher, and finding missing media. The viewer zooms: Ctrl+wheel over the picture at the pointer, a middle-button drag moves around, and the zoom menu beside the preview quality ("Fit · 47 %"; Fit, Shift+Z; 50, 100 (Ctrl+0), 200 %; in and out, Ctrl+= and Ctrl+-). Phase 4C: the inspector on the right places, crops and colours the selected clip (every number can change over time with keyframes: the diamond beside it, marks along the selected clip on the timeline to click, drag (Shift-click chooses several) and right-click for removing them or how they go on, Alt+Left and Alt+Right to step between them), sets its speed (one speed for the clip, or a speed ramp: speed keyframes with the same diamond, two ramp buttons that ease into slow motion from the playhead, a clean slow-motion speed for high-frame-rate recordings, and frame blending; a ramped clip shows its speed as a line on the timeline and "Ramp 100→25%" by its name), sets its sound (volume, pan, fades, drawn on the clip in the timeline), and its picture can be taken hold of in the viewer (drag to move, a corner to resize, double-click to fit). The viewer's Display menu (next to the preview quality) has, under a Timeline heading, compact tracks (every track a thin strip, for an overview of many) and the divider between video and audio (off: one list that scrolls together), and what a click in the ruler moves (the playhead, or the edit needle with the playhead dragged by its handle; also in Settings), all kept in settings; and split view (the selected clip's own picture, raw, beside the timeline's), the viewer in its own window (for another screen; F or a double-click fills that screen, Escape gives it back, closing it brings the viewer back) and full screen. I and O mark in and out: on the Edit page the region's start or end at the playhead.

Phase 5.2: the Library page (the Library tab). Left: Import, the labels with how many files of the open tab have each (click to filter, right-click to rename, recolour, offer in every project or remove), labels offered in every project, the smart filters (Not in a timeline, Needs proxy, End missing, Can't be found, With a note) and Prune (opens the Prune dialog). On top: the Video, Audio, Images and Effects tabs, then the project's lists and "+ New list" (the bar scrolls and fades when full); under them "Find", the filters on as chips, group by, sort, thumbnail size and grid / rows. Video and pictures are a thumbnail grid grouped by label (skim by moving the pointer across one) with "In timeline" and "Needs proxy" badges; sound files are rows with a play button and their waveform in the label's colour. On the right, the file picked: a small player (Space, the arrows, Home and End work it there), mark in and out (I, O), "Add to timeline" (the marked part, also by double-clicking a file), the loudness and true peak of each of its sound streams, each with a one-click level for that stream to be added at, what it is, its labels, lists and note. Marks and levels last for the session, or are saved in the project (Settings › Library).

## Running

```sh
cargo run -p app                         # no project
cargo run -p app -- trip.kiria           # opens (or creates) a project
cargo run -p app -- trip.kiria --open-last-save   # sets aside unsaved work from a crash instead of recovering it
cargo run -p app -- trip.kiria --import match.mkv # imports media at start (repeatable)
cargo run -p app -- trip.kiria --playhead 12.5     # starts with the playhead there (for screenshots)
cargo run -p app -- trip.kiria --play              # starts playing once imports are in (for checks)
cargo run -p app -- trip.kiria --cpu-colour        # converts the viewer's colour on the CPU, to compare with the GPU's picture
cargo run -p app -- --smoke-test         # open, draw 30 frames, close; exit code 1 on failure
cargo run -p app -- --responsiveness-test  # 8-second background job (on the export pool, so waveforms, clip pictures and proxies go on meanwhile); fails unless 99 frames in 100 take under 16 ms of interface work (and none over 50 ms)
cargo run -p app -- --screenshot out.png # save a PNG of the window and close (waits for imports and the viewer's picture first)
cargo run -p app -- --graphics-warning --screenshot out.png  # with the question about a failed start with Vulkan
cargo run -p app -- trip.kiria --import match.mkv --hold-reading 0.4 --screenshot out.png  # with waveforms and clip pictures stopped 40 % read, to see reading in progress
cargo run -p app -- trip.kiria --media-drawer --hold-proxy 0.43 --screenshot out.png  # once a proxy build reaches 43 % and stops there, with the media drawer open
cargo run -p app -- trip.kiria --media-drawer --watch-folder recordings --screenshot out.png  # also watching this folder for new recordings, as if it were a media folder of the launcher (waits for two looks through it)
cargo run -p app -- trip.kiria --find drone --screenshot out.png  # with the media drawer open on what "Find a file" finds for these words (waits for the library index's answer)
cargo run -p app -- trip.kiria --action Templates --screenshot out.png  # with a window opened by a command (any name from the shortcut table: Versions, RemoveSilence, …)
cargo run -p app -- trip.kiria --pointer 640,420 --screenshot out.png  # with the pointer resting there: hover marks and tooltips
cargo run -p app -- trip.kiria --pointer 640,420 --drag-to 640,480 --screenshot out.png  # while the left button drags from the first place to the second
cargo run -p app -- trip.kiria --pointer 640,420 --drag-to 640,480 --release --screenshot out.png  # after that drag was let go: what it did
cargo run -p app -- trip.kiria --pointer 60,700 --right-click --screenshot out.png  # with the menu a right-click opens there
cargo run -p app -- trip.kiria --pointer 60,700 --double-click --screenshot out.png  # after a double-click there (a track's name being typed)
cargo run -p app -- trip.kiria --pointer 900,610 --click --screenshot out.png  # after a click there (a menu that opens on a click, such as the viewer's Display menu)
cargo run -p app -- trip.kiria --import match.mkv --select-first-clip --action SplitView --screenshot out.png  # split view on (the setting is kept: run it again to turn it off)
cargo run -p app -- trip.kiria --select-first-clip --playhead 1 --pointer 500,300 --drag-to 560,330 --screenshot out.png  # with the first clip of the top video track selected (the inspector's values, the handles on its picture), here while its picture is dragged in the viewer
cargo run -p app -- trip.kiria --select-first-clip --pointer 1270,400 --scroll 600 --screenshot out.png  # with the wheel turned 600 points down where the pointer rests (here the inspector, down to its Audio section); with --click as well, a click there once the scrolling has settled (a button scrolled into view)
cargo run -p app -- trip.kiria --select-first-clip --playhead 12 --pointer 700,640 --drag-to 820,640 --release --then Copy --then Paste --screenshot out.png  # commands run once the scripted pointer is done (here: a box chose keyframe marks, which are copied and pasted at the playhead)
cargo run -p app -- trip.kiria --page library --library-tab audio --library-select voice.wav --screenshot out.png  # on a page (library, edit, color, audio, export), the Library on a tab (a type or a list's name) with a file in its detail panel (waits for the index's answer, the thumbnails and waveforms in view and the panel's loudness)
cargo run -p app -- trip.kiria --page library --responsiveness-test  # the responsiveness test on a page
cargo run -p app -- --shortcuts-page clash --screenshot out.png  # with the keyboard shortcuts page open: `filter` (one chip picked), `rebinding` (waiting for keys) or `clash` (keys another command has)
cargo run -p app -- --cheat-sheet keys.html  # write the printable cheat sheet for the shortcuts in settings and exit, without a window
```

The last eighteen are for CI and for checking the look without a screen (`xvfb-run` on Linux).

## Notes

- Opening a project that has unsaved work from a crash recovers it, unless `--open-last-save` is given. The launcher asks which the person wants and passes the flag.
- Resource and Graphics setting changes apply on the next start.
- The shortcut table is made once at start from the usual shortcuts and the changed ones in settings (`ShortcutTable::restored`). The shortcuts page changes that same table, so menus, tooltips, hints and search follow at once; the launcher reads the changes from the same settings file at its next start. While the page waits for new keys the window runs no commands from the keyboard.
- `--decoding-warning` shows the question about video decoding that stopped the app although nothing did, for screenshots.

## Graphics

Which graphics system draws the window, the Graphics row in Settings and the question after a start with Vulkan that never drew a frame all come from the [graphics](../graphics/) crate, shared with the launcher. `main` calls `graphics::prepare` and `graphics::open_window`; the window keeps a `graphics::WindowGraphics`. Automated runs (`--smoke-test`, `--screenshot`, `--responsiveness-test`) write no marker and change no setting. What is in use is on the first line of Diagnostics (Settings, Diagnostics…), under the Graphics setting, in the log (`the window is open`) and in crash reports.
